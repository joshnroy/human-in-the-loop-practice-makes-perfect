EXP-14: why the planner asked for unnecessary human resets

Runs: EXP-14 (code f68a29dd), 4 arms × 5 seeds, 50 cycles × 20 actions, belief-space expectimax at depth min(6, remaining). A reset is gave-up if a Toss was among the root options (the robot was holding the cube) and optional if a Pick was. This is the same rule as the EXP-14 page. Scripts: hitl-pmp-scratch-plots-20260925/unnecessary-resets/.

TL;DR

  • 187/205 unnecessary resets are gave-up resets, and one cause accounts for all of them: a training clock on OpenGripper. When the robot is holding the cube, a reset leaves the gripper closed and empty. The planner's next action is then OpenGripper, in 187/187 of the reconstructed trees. The belief model treats OpenGripper as a skill that improves with practice, although it is a fixed controller that succeeded 197/197 times. Deployment value J depends on OpenGripper (it is how a failed pick is recovered), so the model forecasts that each OpenGripper attempt raises J. Freezing only OpenGripper's clock inside the search flips 187/187 of these resets to Toss. Freezing Pick's clock flips 0/187, and freezing the reset's own clock flips 0/187.
  • The gave-up resets win by tiny margins: median 1.3e-05, with 90% below 9.3e-05. At λ=0 the objective has no cost term, so any positive margin is enough, and Model A λ=0 has the most gave-up resets (90). The search depth matters. Gave-up resets are chosen in 67/385 holding decisions at depth 2, 40/438 at depth 4 and 65/6064 at depth 6. At depth 1 there are none (0/461), because OpenGripper can no longer follow the reset. In a short search, the one OpenGripper tick after a reset is a large share of everything the search can gain.
  • The 18 optional resets have a different cause. All of them happen with the bin on the far side and move it to the robot side. The failure-effect model is learned separately for each exact symbolic context and treats an unseen context as "nothing changes". 8/18 of these resets happen at the 3rd action of the whole run. At that point the only failure the model has seen is one far-side greedy toss, in which the cube fell and had to be picked again. A robot-side failure is unseen, so it is imagined to leave the cube in hand, ready to toss again: an optimistic identity effect. The other 10 happen later, when the model has seen dozens to hundreds of robot-side failures (the cube stays re-pickable) and only 1–4 far-side ones per mode. Letting unseen exact contexts borrow the effects observed in other contexts flips 18/18 of them to Pick. No clock freeze flips any (0/18). In the real data, far-side failures strand the cube more often, so it is not settled that the later ones are wrong.
  • Hypotheses from the code review, verified: (1) the reset's own clock has no effect (0/187; J never reads the reset belief). What matters is the fixed-skill clock the reset unlocks, and that clock is OpenGripper's, not Pick's. (2) The ε-random toss success of 0.25 against the observed 314/3683 is a real model error but a minor driver (16/187 gave-up, 2/18 optional). (3) The identity assumption for unseen failure contexts does not drive the gave-up resets: every toss context there had been seen (187/187). It does drive the optional ones. (4) Deployment horizon 4 matches the evaluation (eval tasks run 2 or 4 steps). With horizon 8 OpenGripper matters less and 178/187 gave-up resets flip, but that would misstate the evaluation, so it is a sensitivity, not a fix.

Real OpenGripper attempts total 91 / 49 / 36 / 21 over the 5 seeds of each arm, close to that arm's gave-up count (90 / 45 / 33 / 19). OpenGripper is practised almost only because of these resets.

Side effects of the top fix, measured on the 963 sampled decisions: freezing both fixed-controller clocks changes 1/847 non-reset choices and 7/116 reset choices (Reset→Reset: 2, Reset→Toss: 5, Pick→Reset: 1).

3. Suggested fixes (model-side, ranked by expected impact)

1. Parameter-free skills should not have a practice-driven learning term. PickCube and OpenGripper are fixed controllers (consultation no_sampler). Since #370 their attempts advance a training clock (SKILL_BELIEF_MODELS, PracticeExampleSource.OUTCOME). Model A's curve prior and Model B's drift η ≥ 0 then forecast improvement from every attempt, and nothing in the data can cancel that forecast for a skill that is barely attempted. Model their competence as stationary: uncertain, updated by success/failure, but not trending with practice. Keeping the information value of observing them is fine; in the counterfactuals the information value alone never produced a gave-up reset.
Evidence: OpenGripper clock frozen → 187/187 gave-up resets flip to Toss. Pick clock frozen → 0/187. On 963 sampled decisions (every 20th of each run), freezing both clocks changed 1/847 non-reset choices and 7/116 reset choices (Reset→Reset: 2, Reset→Toss: 5, Pick→Reset: 1). So it is not side-effect free: it can occasionally prefer a reset over a pick. Real OpenGripper outcomes: 197/197 successes. Expected impact: removes about 187/205 of the unnecessary resets (about 18/run in Model A λ=0). This is inferred from single-decision counterfactuals; a closed-loop rerun is needed to confirm it.
2. Failure effects should carry uncertainty in sparse contexts. EmpiricalFailureEffects uses exact-context maximum likelihood, falling back to identity when a context is unseen. With 0–4 far-side observations per mode it is either blind (identity) or overconfident. A hierarchical or partially pooled model (a context-specific estimate that shrinks towards the same skill's effects in related contexts, with the posterior predictive used in search) would let the planner weigh far-side practice on what it has actually seen.
Evidence: letting unseen exact contexts borrow the observed effects flips 18/18 optional resets to Pick (and 2/187 gave-up). Caveat: in the real data a failed greedy far-side toss stranded the cube in 30/48 cases, against 0/1433 on the robot side. So the full pooling tested here is optimistic, and a calibrated model may still choose to move the bin. Expected impact: at most about 4 resets/arm; uncertain.
3. Toss competence should depend on where the bin is. One toss belief is shared across bin sides (#344), but greedy success was 2744/4177 with the bin on the robot side against 45/93 on the far side. The evaluation places the bin on the far side (bin x ≥ 1.6, barrier at x = 1.3), yet 7797/7953 practice tosses had the bin on the robot side. Under a side-agnostic belief, a reset that moves the bin to the robot side (every optional reset) looks free of any transfer cost. Evidence: inferred, not tested; testing it needs a model change, not a re-solve. Expected impact: unknown for the resets, and possibly larger for what practice is worth.
4. The ε-random toss success should be learned, not fixed at 0.25. Observed: 314/3683. A Beta belief on the ε-branch rate, updated by the ε-random outcomes, is the model-side version. Evidence: with the observed rate, 16/187 gave-up and 2/18 optional resets flip. Expected impact: small.

Not a fix: the deployment horizon (4 is what the evaluation uses) and λ. At λ=0 a reset is free in the objective. At λ=3e-6 it costs 5×3e-6 = 1.5e-5 in J, already included in those arms' values, and the resets still won. Among λ=0 gave-up resets, 69/90 (Model A) and 10/33 (Model B) have margins below 1.5e-5. These are statements about the objective, not suggestions to add a penalty.
