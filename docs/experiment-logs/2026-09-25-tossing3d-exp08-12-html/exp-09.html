EXP-092026-09-25

Practice cycle length — 20 / 30 / 40 / 50 / 80 / 100 actions per cycle at ε = 0.3

Practice sideRobot side only — FORCED by code, not chosen by the planner. From #366 (first commit 57196f0a, 2026-09-25 00:31; stack commits 47c30231 / fe73dc1c / 8bb9a337) practice resets could only put the bin on the robot side and every practice scene was rebuilt with the bin on the robot side. Josh reversed this on 2026-09-25 ~21:40 (the planner must choose); results here are conditional on forced same-side practice.
QuestionHow does eval scale with the number of practice actions per cycle, holding 10 cycles (10 classifier refits) and ε fixed?
HypothesisPre-registered. Toss learning is success-starved, so more actions per cycle reach the first success sooner and give the classifier more successes per refit: eval improves with cycle length, with diminishing returns once each cycle already yields several successes (expected knee around 40–50 actions).
Results TL;DRNo monotone effect of cycle length on final eval (one seed, no inference): 20 → 5/10, 30 → 7/10, 40 → 4/10, 50 → 4/10, 100 → 6/10; 80: FAILED mid-practice: a pick dragged the bin 14–21 cm and turned it, so at the sampled standoff no collision-free toss pose existed (toss-pose feasibility check, not the arm motion planner); plotted up to its last eval (5/10 after cycle 6). What does change: every length ≥ 30 gets its first practice success in cycle 1 (20 actions: cycle 5), and area under the curve grows with length (20/110 at 20 actions, 45/110 at 30 and 50, 71/110 at 100). Eval swings 3–4 tasks between consecutive cycles, which swamps the final-cycle comparison.
Code noteLaunched on d7b7ba30, before EXP-07d's change (pick/open/reset counts stay at 0). EXP-07d found that makes essentially no behavioural difference.
Armsλ = 0, ε = 0.3, 10 cycles, --max-steps-per-interaction ∈ {20, 30, 40, 50, 80}, seed 0; the 100-action point is EXP-08c's run (reused). Model A + grid, notebook-matched code, evidence non-ε. One seed per arm: raw numbers only, no inference.
StatusDone — 5/6 finished, 1 failed (80 actions, bin-movement crash).
