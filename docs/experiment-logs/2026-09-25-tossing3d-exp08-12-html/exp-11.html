EXP-112026-09-25

Practice cycle length on Model B + grid — EXP-09 repeated with the local-trend model

Practice sideRobot side only — FORCED by code, not chosen by the planner. From #366 (first commit 57196f0a, 2026-09-25 00:31; stack commits 47c30231 / fe73dc1c / 8bb9a337) practice resets could only put the bin on the robot side and every practice scene was rebuilt with the bin on the robot side. Josh reversed this on 2026-09-25 ~21:40 (the planner must choose); results here are conditional on forced same-side practice.
QuestionDoes practice cycle length affect Model B the same way it affects Model A?
HypothesisPre-registered. At λ = 0 the competence model does not choose throws (the classifier does) and the planner practises to budget regardless, so Model B's eval curves track Model A's EXP-09 counterparts closely at every cycle length (as in EXP-07c, where they differed only in the last two checkpoints).
Results TL;DRSupported (one seed, no inference): Model B tracks Model A arm for arm. 40 and 50 actions are identical to Model A every cycle (final 4/10 each); 20 actions identical until the final cycle (3/10 vs 5/10); 30 actions diverge from cycle 4 (final 8/10 vs 7/10). 80 actions: FAILED mid-practice: a pick dragged the bin 14–21 cm and turned it, so at the sampled standoff no collision-free toss pose existed (toss-pose feasibility check, not the arm motion planner); plotted up to its last eval (6/10 after cycle 5; video below). 100 actions (shared with EXP-10): final 7/10 vs Model A 6/10.
Code noteLaunched on d7b7ba30, before EXP-07d's change (pick/open/reset counts stay at 0). EXP-07d found that makes essentially no behavioural difference.
Arms--pomdp-competence-model local_trend, notebook ρ = 0.9, λ = 0, ε = 0.3, 10 cycles, --max-steps-per-interaction ∈ {20, 30, 40, 50, 80, 100} (100 shared with EXP-10), seed 0. Model B + grid, notebook-matched code, evidence non-ε. One seed per arm: no inference.
StatusDone — 5/6 finished, 1 failed (80 actions, bin-movement crash).
