# POMDP decision traces and practice videos

POMDP runs with `--output-dir` automatically write `pomdp_decisions.jsonl`.
Each decision has its seed, zero-based practice cycle, decision number, true
atoms, selected action, value, model configuration, and full expectimax trace.
Dispatches, observed outcomes, and end-of-cycle refits are separate records.

Inside a decision, node 0 is the root. `stop_value` is the immediate stopping
value; `action_value` gives each competing action's expected value. `sample`
records the actual theta and policy/cost-adjusted values used. `branch`
records successor state, posterior, probability, cost, recursive value and
weighted contribution. A successor is identified by state, belief, accumulated
cost and remaining horizon; cached successors reuse their existing node.
`choice` distinguishes a horizon leaf from a value-maximizing decision. STOP
wins ties. Tracing does not call the model again or consume extra randomness.

Practice MP4s have a right-hand scrolling event panel. It preserves repeated
skills, marks human resets, and marks early interaction completion. The latest
eight entries are retained on screen; `practice_events.jsonl` keeps the full
history with zero-based cycle indices and transition counts. Evaluation videos
keep the existing status layout.

For full-scene Tossing3D videos, omit `--no-scene-bg`; the background is on by
default. The renderer includes measured cube dimensions and scored-region
dimensions, in addition to cube position and the success predicate. The scored
region is not the physical bin footprint. Captions on substep frames describe
the state at the end of the skill, not each individual physics tick.

The reset-free diagnostic configuration uses `--practice-reset-policy never`
and `--ask-for-reset-cube-bin-cost 0.00001`. This enables the human cube/bin
reset skill, not automatic resets. Checkpoint/resume support has been removed.
Old recordings and traces are not retroactively regenerated by these changes.

The CLI defaults to 100 theta samples per search state, configurable with
`--pomdp-num-samples`. The video sidebar plots the actual root STOP/action
values at each decision, highlighting the maximum in green. Only available
actions are plotted. In linear-cost mode, values include the cost penalty; in
hard-budget mode, values are deployment success estimates subject to affordability.
The improvement-potential display is the best available practice value minus STOP.
No extra search or random draws are performed for the chart.

Event JSONL logs include a UTC `timestamp` and monotonic `elapsed_seconds`
since the shared logging clock was initialized in that process. These are
write times, not reconstructed simulator tick times: some state/episode events
are buffered before writing. Search decisions additionally record
`search_duration_seconds`, excluding serialization and disk writing. Nested
search events also carry timestamps. Existing progress and sweep timing logs
retain their own run-boundary clocks; use wall timestamps to align them.
`stats.json` gains deterministic session-end records but no wall-clock timestamps.

A separate competence panel uses a fixed 0–1 scale. It shows the current
toss, pick, and gripper-opening posterior means (before any pending end-of-cycle
refit). Only the human reset success probability is fixed.
These are POMDP model estimates, not empirical success fractions and not the
executor's separate EES competence estimates. STOP is not a skill competence.
The panel is read without updating the belief or drawing samples.

Session-end records distinguish `planner_stop`, generic `interaction_complete`,
and `session_action_cap`. Counts include human reset actions and exclude STOP.
The final video banner uses the same reason. Reaching the action cap does not
trigger an extra search: any displayed values belong to the last real decision.
